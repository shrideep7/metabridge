# Introduction

MetaBridge is the Enterprise Data Modernization Operating System — one deployable platform to **assess, migrate, govern, and operate** any legacy data estate. It is built for the firms that modernize data for a living, and it is **deterministic and honest by design**: engines compute from evidence, modeled figures are labelled as such, and every AI action is confidence-scored, governed, and captured in a tamper-evident audit trail.

## What MetaBridge is

Enterprise data modernization is a program, not a project — and today it is fragmented across a dozen point tools: a discovery scanner here, a hand-rolled SQL transpiler there, spreadsheets for lineage and cost, a separate governance review, and no single trace tying any of it together. That fragmentation is where estimates blow out, migrations stall, and a client's risk team says no.

MetaBridge collapses the whole program onto one platform. It parses **18 source formats** into shared canonical models, converts them to cloud and dbt targets, classifies sensitive data and evaluates residency and masking policy, models cost and ROI, generates the documentation set, and monitors the result — all over a single typed model spine, inside a single deployable unit that runs in your own boundary.

It is architected as a **modular monolith**: one deployable process (a FastAPI web app served by uvicorn, plus a `metabridge` CLI) whose independent engines compose over a shared model spine through a registry/kernel. There is no service mesh, no message broker, and no runtime database — durable state lives on a mounted file volume. See [Architecture](architecture.md) for the full conceptual and physical picture.

## Who it is for

MetaBridge is a **white-labelable delivery accelerator** with two audiences in view:

- **System integrators and large enterprises that modernize data for a living** — the delivery teams who need to move faster on assessments and migrations, produce defensible numbers, and embed modernization into a repeatable delivery pipeline via the CLI and REST API.
- **Their regulated enterprise clients** — the estate owners and risk teams who have to accept the automation. For them, MetaBridge is deterministic (numbers are computed from evidence, not generated by an LLM), governed by default (RBAC, human approval, tamper-evident audit), and **single-tenant self-hosted** so schemas, SQL, and PII/PHI never leave their boundary.

## The lifecycle: assess → migrate → govern → operate

Every engine reads and writes the same canonical models, so a modernization program flows end to end on one platform rather than across disconnected tools.

| Stage | What happens | Engines |
|---|---|---|
| **Assess** | Discover and inventory the estate, build the typed graph, score readiness, quantify technical debt, model cost, and evaluate security posture. | Enterprise Data Estate · Digital Twin · AI Readiness · Technical Debt · FinOps · Security Intelligence |
| **Migrate** | Detect and parse sources into canonical IR/CIR, lift intent, convert to cloud/dbt/Informatica targets with an AI review + approve-and-apply queue, and score conversion confidence. | Semantic Intelligence · Migration Engine · Pipeline Studio · Validation |
| **Govern** | Classify PII/PHI/financial data, evaluate residency and masking policy, and produce audit evidence — with a tamper-evident audit chain underneath. | Governance Engine · Security Intelligence · Audit service |
| **Operate** | Generate the documentation set, monitor pipeline / agent / connector health with SLA and alerting, and run the governed agentic layer. | Documentation · Observability · Agent Orchestration |

## The six engine categories at a glance

MetaBridge ships **16 core engines** organized into six categories, each declaring the canonical models it consumes and produces so the platform can render cross-platform lineage and a live health roll-up.

| Category | Engines | What it does |
|---|---|---|
| **Estate & topology** | Enterprise Data Estate · Digital Twin | Multi-source discovery and one typed estate graph with deterministic analytics (blast radius, lineage, impact, migration waves). |
| **Modernization** | Semantic Intelligence · Migration Engine · Pipeline Studio · Validation | Lift parsed IR into platform-neutral CIR, convert sources to targets, generate governed pipelines and orchestration, and score conversion confidence. |
| **Governance & security** | Governance Engine · Security Intelligence | Classify sensitive data and evaluate residency/masking policy; assess security posture and compliance coverage mapping. |
| **Intelligence** | AI Readiness · Technical Debt · FinOps | Score AI-readiness dimensions and roadmap, detect unused/duplicate/dead assets and cost the cleanup, and model cloud cost, ROI, and sizing. |
| **Operations** | Documentation · Observability · Agent Orchestration | Generate the enterprise documentation set, monitor run history and modeled resource health, and run the governed agentic layer. |
| **Extensibility** | Marketplace · Plugin SDK | Install signed connectors, validators, AI skills, templates, and accelerators; extend the platform through a uniform plugin contract. |

Because the kernel enumerates engines through a registry, adding an engine plugs it straight into the existing graph, governance, and audit. See [Engines](engines.md) for the full catalog.

## The philosophy: deterministic, governed, self-hosted

Three commitments run through the whole platform and shape how it can be trusted in regulated delivery.

### Deterministic

Engines **compute from evidence** — they do not invent numbers. Modeled figures are labelled **"modeled, not measured"** and inferred estate facts are **"topology, not telemetry"**, so a reader always knows the provenance of a number. The optional **LLM assist is advisory-only and off by default**; it never sits on the platform's core logic. You opt in with the `llm` extra and an API key, and the deterministic result stands on its own without it.

### Governed

Governance is structural, not an add-on. RBAC guards every route across owner / admin / engineer / viewer roles. Every consequential AI action is **confidence-scored from real evidence**, requires **human approval** with **segregation of duties** (the requester cannot approve their own proposal — `agents:approve` is a distinct permission), and is written to a **tamper-evident, HMAC-keyed audit chain that is re-verified on read**. Marketplace extensions are Ed25519-signed. Governance produces **audit evidence and compliance mapping — it is not a certification** (no SOC 2 or ISO claim). See [Governance & Security](governance-security.md) and [Agentic AI](agentic-ai.md).

### Self-hosted

MetaBridge is **single-tenant** and runs inside your own boundary — self-hosted or in your VPC — as a single container plus one state volume. Schemas, SQL, and sensitive data stay in one process; there is no runtime database and no external service dependency for the core. The web console (`/console`), REST API (`/api`, OpenAPI at `/docs`), and CLI are three co-equal front doors over the same engines and the same governance. See [Deployment](deployment.md).
