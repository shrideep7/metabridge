## 1. What it is

Six KPI tiles across the top of the Overview page, plus a **Summarize** dropdown that controls how
many recent runs three of them cover.

## 2. Why it exists

To answer, in one glance and without opening any job, four questions:

| Question | Tile |
|---|---|
| What are we connected to? | Connected systems |
| How much have we modernized? | Assets analyzed · Modernizations · Models scaffolded |
| Can we trust the output? | Validation pass rate |
| What still needs a person? | Manual review items |

It is a **roll-up of work already finished**. Nothing here queries a source system live — a tile
only moves when a job completes or a connection changes state.

## 3. What you see

```
Overview                                Summarize [ Last 8 runs ▾ ]  [Connect source] [Start modernization]
Monitor your data estate, modernization programs, pipelines, and validation health.

┌────────────────┬────────────────┬────────────────┬────────────────┬────────────────┬────────────────┐
│ CONNECTED      │ ASSETS         │ MODERNIZATIONS │ MODELS         │ VALIDATION     │ MANUAL REVIEW  │
│ SYSTEMS        │ ANALYZED       │                │ SCAFFOLDED     │ PASS RATE      │ ITEMS          │
│ 2              │ 54             │ 34             │ 323            │ 25%            │ 0              │
│ 2 saved        │ across 8 of 34 │ 3 in flight    │ 11 scaffold    │ from 8 of 34   │                │
│                │ runs           │                │ runs           │ runs           │                │
└────────────────┴────────────────┴────────────────┴────────────────┴────────────────┴────────────────┘
```

Each tile is a label, a big number, and a sub-label giving context for that number.

## 4. What it means

### Connected systems
Saved connections that are **proven reachable right now**. A connection counts only if it is
started *and* its last stored connection test passed — an untested, failed, stopped, or
credential-missing connection is never reported as connected. Sub-label is the total number saved,
so `2` over `2 saved` means everything you saved is working; `1` over `4 saved` means three are not.

### Assets analyzed
How many individual objects (tables, views, transformation assets) the conversion engine has
mapped. It is the sum of mapped objects across the runs in the current **Summarize** window — the
sub-label `across 8 of 34 runs` means eight runs were opened and read out of thirty-four that
exist. **This is not the size of your data estate**; it is how much of it has been through a
conversion.

### Modernizations
Completed conversion programs. The sub-label counts conversion jobs that have **not** finished —
queued, running, or failed — as "in flight". Always whole-estate; the Summarize window does not
touch it.

### Models scaffolded
Total pipeline models generated by Pipeline Studio, summed across every completed scaffold run.
Sub-label is how many scaffold runs contributed. Also whole-estate.

### Validation pass rate
Share of validated runs whose verdict was `PASS` or `PASS_WITH_WARNINGS`. Runs with no verdict at
all are excluded from both sides of the fraction, so this is *"of the runs we actually validated,
how many were clean"* — not *"how much of my estate is validated"*. Windowed.

### Manual review items
Work the converter could not finish automatically. Three things are added together:

| Part | Meaning |
|---|---|
| Objects marked `NEEDS_MANUAL_WORK` | Converted with a blocker attached |
| Objects marked `FAILED` | Could not be converted at all |
| Project-level `MANUAL` / `ERROR` issues | Procedures, unparseable files — blockers not attached to any single object |

The third part matters: without it a run could report "100% of objects converted" while hundreds
of files were silently unreadable. Including it keeps the headline honest. Windowed.

### The Summarize dropdown
Chooses how many of the most recent **completed conversions** get opened and summarized.

## 5. Where the data comes from

Nothing on these tiles is predefined or seeded. Two calls, then arithmetic in the browser:

| Source | Feeds |
|---|---|
| Saved connection store | Connected systems |
| Job metadata (`<workspace>/jobs/*/meta.json`) | Modernizations, Models scaffolded |
| Per-run conversion report (`<job>/output/conversion_report.json`) | Assets analyzed, Validation pass rate, Manual review items |

Workspace root is `~/.metabridge` unless `METABRIDGE_DATA_DIR` overrides it. Connection *state* is
derived at read time, not stored.

## 6. Behaviour and rules

- **Two kinds of tile.** Connected systems, Modernizations and Models scaffolded are
  **whole-estate** — cheap to compute from job metadata, always complete. Assets analyzed,
  Validation pass rate and Manual review items are **windowed** — each needs a run's report file
  opened, so they cover only the selected window. This is why *Modernizations = 34* can sit next to
  *Assets analyzed = 54 across 8 of 34 runs* without either being wrong.
- **Window options adapt to your data.** Only steps that would actually narrow the list are
  offered, plus "All N runs" — no "Last 50" when you have 34. The control hides entirely below nine
  runs, where there is nothing to choose.
- **Window default is Last 8**, persisted per browser. A saved choice that no longer narrows
  anything reads as "All" without being overwritten, so it returns if the estate grows.
- **The window also drives the Modernization history table** below the cards — see
  [02 — Modernization history](02-active-modernizations.md).
- **Runs missing a report are skipped silently.** The sub-label counts runs actually read, so it
  can be lower than the window you picked.
- **Refresh** happens on page visit and after any convert / govern / scaffold job completes. There
  is no polling.

## 7. Known gaps

- **A genuine zero renders as `--`** on five of the six tiles, so "zero connected systems" and "no
  data yet" look identical. Manual review items is the exception — it shows a real `0`.
- **Manual review items has no sub-label**, unlike the other five, and no click-through. The actual
  work items exist per run as `manual_workbook/` (skeleton files plus a triage README) and
  `manual_queue.csv` (Jira/Excel import) inside the job's output, but the tile does not link to
  them — it is informational, not actionable.
- **No server-side aggregate endpoint.** Every client recomputes the same sums from raw job files.
- **Job history caps at 100**, so "All runs" strictly means "all of the newest 100".
- **Assets analyzed is easily misread** as estate size. It counts converted objects, not objects
  discovered by Data Estate.
